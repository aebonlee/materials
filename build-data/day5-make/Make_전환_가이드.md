# DAY 5 — n8n 대신 Make 로 하기

교재 PART 05 는 n8n 화면을 기준으로 쓰여 있습니다. 이 문서는 같은 실습을 **Make** 에서 하는 방법입니다.
만드는 것도, 배우는 것도 같습니다 — **수집(입력) → 가공(변환) → 출력(전달)** 구조와
「모든 건은 기록하고, 이상한 건만 알린다」는 설계 원칙입니다.

Make 에서는 워크플로를 **시나리오(Scenario)**, 노드를 **모듈(Module)** 이라고 부릅니다.

---

## 1. 무엇이 무엇에 대응하나

| 교재(n8n) | Make | 하는 일 |
|---|---|---|
| 점검표 제출 폼 (Form 트리거) | **Webhooks → Custom webhook** 또는 **Google Drive → Watch files** | 점검표 사진을 받는다 |
| 사진 준비 (Code) | 모듈 없이 **매핑으로 처리** | 사진을 API 가 받는 형태로 바꾼다 |
| Gemini 호출 (HTTP Request) | **HTTP → Make a request** | 사진에서 점검 내용을 뽑는다 |
| 응답 정리 (Code) | **Tools → Set multiple variables** (+ 필요하면 JSON → Parse JSON) | 값 일곱 개로 정리한다 |
| 시트 적재 (Google Sheets) | **Google Sheets → Add a row** | 모든 건을 시트에 남긴다 |
| 불량 있음? (IF) | **Router + 경로에 필터(Filter)** | 갈림길을 만든다 |
| Slack 알림 | **Gmail → Send an Email** | 불량 건만 알린다 (이번 차수는 메일로) |

**IF 노드가 Make 에는 없습니다.** 대신 라우터로 길을 나누고 각 길에 필터를 겁니다.
교재가 "아래쪽 길에는 아무것도 연결하지 않는다"고 한 부분은, Make 에서는 **경로를 하나만 만들고
그 경로에 필터를 거는 것**으로 같아집니다.

## 2. 표현식 문법 차이

| | n8n | Make |
|---|---|---|
| 앞 모듈 값 | `{{ $json['장비ID'] }}` | `{{2.장비ID}}` — 앞에 붙는 숫자가 **모듈 번호** |
| 현재 시각 | `{{ $now.toFormat('yyyy-MM-dd HH:mm') }}` | `{{formatDate(now; "YYYY-MM-DD HH:mm")}}` |
| 인자 구분 | 쉼표 `,` | **세미콜론 `;`** |

Make 는 모듈마다 번호가 붙고, 값을 꺼낼 때 **그 번호로** 가리킵니다.
화면에서 값을 고르면 자동으로 들어가므로 손으로 적을 일은 많지 않습니다.

## 3. 단계별 설정값 (그대로 쓰세요)

### ① 트리거 — 점검표 사진 받기
- 쉬운 길: **Google Drive → Watch files**. 공유 폴더 하나를 정해 두고 거기에 사진을 올립니다.
- 교재와 같은 즉시 처리: **Webhooks → Custom webhook**. 주소가 생기면 그 주소로 사진을 보냅니다.
- 어느 쪽이든 다음 단계에서 **파일 데이터**를 쓸 수 있어야 합니다.

### ② Gemini 호출 — HTTP → Make a request
```
Method  : POST
URL     : https://generativelanguage.googleapis.com/v1beta/models/gemini-3.5-flash:generateContent
Headers : 이름 x-goog-api-key   값 (1일차에 받아 둔 키)
Body type : Raw   ·   Content type : application/json
```
Request content (사진 데이터와 MIME 타입만 화면에서 끼워 넣으세요):
```json
{"contents":[{"parts":[
  {"inline_data":{"mime_type":"image/jpeg","data":"(여기에 사진 데이터)"}},
  {"text":"이 사진은 굴착기 일일점검표입니다. 아래 형식의 JSON 으로만 답하세요.\n{\"장비ID\": \"\", \"점검일자\": \"YYYY-MM-DD\", \"점검자\": \"\",\n \"항목\": {\"<항목명>\": {\"판정\": \"양호|불량\", \"비고\": \"\"}}, \"특이사항\": \"\",\n \"불량항목\": [\"<불량인 항목명, 비고가 있으면 괄호로 함께>\"], \"불량수\": 0}\n항목명은 사진에 적힌 그대로 쓰고, JSON 외의 말은 쓰지 마세요."}
]}],"generationConfig":{"temperature":0}}
```
- **여기가 오늘 가장 잘 막히는 자리입니다.** 사진을 base64 로 넣는 매핑이 비어서 나가면
  응답이 오지 않거나 빈 값이 옵니다. 실행 기록에서 보낸 본문을 열어 `data` 가 비어 있지 않은지 먼저 보세요.
- 그래도 막히면 **Google Gemini AI → Analyze image** 모듈로 바꿔도 됩니다. 사진을 그대로 받아 주므로
  base64 를 다룰 일이 없습니다. 다만 「헤더 인증」을 손으로 만들어 보는 경험은 건너뛰게 됩니다.

### ③ 응답 정리 — Tools → Set multiple variables
모델 응답에서 값을 꺼내 **일곱 개**로 정리합니다. 시트 열 이름이 곧 이 이름입니다.

앞의 HTTP 모듈이 3번, 그 응답을 푼 Parse JSON 이 4번이라면 이렇게 됩니다.

| 변수 이름 | 값 |
|---|---|
| 제출시각 | `{{formatDate(now; "YYYY-MM-DD HH:mm")}}` |
| 장비ID | `{{4.장비ID}}` |
| 점검일자 | `{{4.점검일자}}` |
| 점검자 | `{{4.점검자}}` |
| 불량수 | `{{4.불량수}}` |
| 불량항목 | `{{join(4.불량항목; ", ")}}` |
| 특이사항 | `{{4.특이사항}}` |

**모델 응답이 글자 덩어리로 오므로 JSON → Parse JSON 을 한 번 거칩니다.** 응답 글에
```json 표시가 붙어 오는 경우가 있어 떼어 내고 넣습니다.

```
{{trim(replace(replace(3.data.candidates[1].content.parts[1].text; "```json"; ""); "```"; ""))}}
```

Make 는 배열이 **1부터** 셉니다. n8n·파이썬의 `[0]` 이 여기서는 `[1]` 입니다.

> **왜 불량수를 모델에게 시키나요.** 교재(n8n)는 코드 노드에서 `항목` 을 훑어 셉니다.
> Make 의 기본 흐름에는 코드 노드가 없고, 항목명이 사진마다 달라 키를 미리 알 수 없어
> 화면 매핑만으로는 세기 어렵습니다. 그래서 **프롬프트에 `불량항목`·`불량수` 를 함께
> 요청**했습니다. `항목` 은 교재 그대로 남아 있으니 원본을 확인하는 데는 지장이 없습니다.

### ④ 시트 적재 — Google Sheets → Add a row
```
스프레드시트 : 점검표_자동수집
시트         : 수집
열           : 제출시각 · 장비ID · 점검일자 · 점검자 · 불량수 · 불량항목 · 특이사항
```
**라우터보다 앞에 둡니다.** 뒤에 두면 불량 건만 쌓여서, 수집 건수·결측률 같은 품질 지표를 볼 수 없습니다.
교재가 짚는 설계 핵심이 이 자리입니다.

### ⑤ 갈림길 — Router + 필터
```
필터 이름 : 불량 있음
조건      : 불량수   Greater than   0     (조건 유형을 숫자로!)
```
글자로 비교하면 「10」이 「2」보다 작다고 판정됩니다. 교재가 경고한 그 함정이 Make 에서도 같습니다.

### ⑥ 알림 — Gmail → Send an Email

교재는 Slack 으로 알립니다. **이번 차수는 Gmail 로 합니다** — 수강생이 새로 가입할 서비스가
없고, 시트 때문에 어차피 구글 계정을 연결하기 때문입니다. **알리는 자리가 무엇이든
「모든 건은 기록하고 이상한 건만 알린다」는 설계는 그대로입니다.**

```
받는 사람 : (담당자 메일 주소)
제목      : [점검표 불량] {{장비ID}} · {{점검일자}} — 불량 {{불량수}}건
```
본문:
```
장비: {{장비ID}} / 점검일자: {{점검일자}}
불량 {{불량수}}건 — {{불량항목}}
점검자: {{점검자}}
특이사항: {{특이사항}}
```

> **연결이 시트와 따로입니다.** Make 에서 Google Sheets 는 `google`, Gmail 은 `google-email`
> 로 **연결 종류가 다릅니다.** 같은 구글 계정이라도 승인을 한 번 더 받아야 합니다.
> 시트가 되는데 메일이 안 되면 십중팔구 이 자리입니다.

## 4. 확인할 것

- 시나리오를 한 번 실행하고 **실행 기록(History)** 에서 모듈마다 들어온 값과 나간 값을 엽니다.
- 시트에 **모든 제출**이 한 줄씩 쌓이는가 (불량 건만 쌓이면 라우터 앞뒤가 바뀐 것입니다)
- 불량이 없는 사진을 넣었을 때 **메일이 가지 않는가**
- 불량이 있는 사진을 넣었을 때 메일 제목·본문의 값이 **비어 있지 않은가**

## 5. 자격증명 세 가지 (교재와 같습니다)

| 방식 | 어디에 | Make 에서 |
|---|---|---|
| 헤더 인증 | Gemini | HTTP 모듈의 Headers 에 `x-goog-api-key` |
| OAuth | Google Sheets | 모듈에서 구글 계정 연결 |
| OAuth (별개) | Gmail | 모듈에서 구글 계정 연결 — **시트와 연결 종류가 다릅니다** |

## 6. 완성 예제

강사 계정(Make)에 **「DAY 5 예제 — 점검표 사진 자동 접수 (Make)」** 시나리오를 만들어 두었습니다.
① Custom webhook → ② HTTP(Gemini) → ③ Parse JSON → ④ Set multiple variables → ⑤ Router(필터: 불량수 > 0)
까지가 들어 있습니다. 수업에서 화면으로 함께 봅니다.

- Gemini 키는 넣어 두지 않았습니다. HTTP 모듈의 `x-goog-api-key` 값에 각자 키를 넣습니다.
- **Google Sheets 적재와 Gmail 알림은 계정 연결이 필요해 빠져 있습니다.** 연결을 만든 뒤
  ④와 ⑤ 사이에 Sheets → Add a row 를, ⑤의 경로에 Gmail → Send an Email 을 붙이면 완성됩니다.
- 웹훅 주소는 시나리오 첫 모듈을 열면 보입니다. **주소를 아는 사람은 누구나 이 시나리오를
  실행할 수 있으므로** 화면 공유·캡처에서 가리고, 수업이 끝나면 시나리오를 꺼 둡니다.

## 7. 카카오톡으로 알릴 수 있나 (2026-09-08 확인)

「사이트에 카카오 로그인을 이미 쓰고 있으니 되지 않겠느냐」는 물음에 대한 답입니다.
**절반은 맞고 절반은 다릅니다.** 아래는 카카오 개발자센터 문서에서 확인한 사실입니다.

### 맞는 부분

카카오톡 메시지 API 는 **카카오 로그인이 전제**입니다. 앱 등록·Redirect URI 는 이미 있습니다.
그리고 **「나에게 보내기」는 비즈니스 앱 전환도, 별도 검수도 필요 없습니다.**

```
POST https://kapi.kakao.com/v2/api/talk/memo/default/send
Authorization: Bearer ${ACCESS_TOKEN}
Content-Type: application/x-www-form-urlencoded;charset=utf-8
```

필요한 것은 동의항목 **`talk_message`** 하나입니다. 강사 본인 폰으로 알림을 받아 보이는
데모라면 이걸로 충분합니다.

### 다른 부분 — 그래서 이번 차수에 안 쓰는 이유

- **사이트의 카카오 로그인 토큰을 Make 가 쓸 수 없습니다.** 사이트 로그인은 Supabase 가
  대행하고 토큰도 Supabase 가 들고 있습니다. Make 는 별도로 인가를 받아야 합니다.
- **Make 에 카카오 커넥터가 없습니다.** HTTP 모듈로 직접 부르게 되는데,
  **REST API 액세스 토큰은 6시간이면 만료**됩니다.
- 리프레시 토큰(2개월)으로 갱신할 수는 있지만, **갱신하면 리프레시 토큰도 새로 발급되고
  옛것은 폐기**됩니다. 즉 Make 안에 토큰을 저장하고 굴리는 장치(데이터 스토어 + 갱신 모듈)를
  따로 만들어야 합니다. **이 토큰 관리가 오늘의 주제(수집 → 가공 → 출력)를 잡아먹습니다.**
- **「친구에게 보내기」는 권한 신청(검수)이 필요**하고 한 번에 5명·일/월 쿼터가 있습니다.
- **알림톡**(Make 의 `solapi` 앱)은 발신프로필 등록·템플릿 사전승인·건당 과금입니다.

### 준비물은 만들어 두었고, 설정은 나중에 합니다 (2026-09-08 대표 지시)

**이번 차수 알림은 Gmail 입니다.** 카카오톡은 아래 준비물을 만들어 둔 채 **꺼 두었습니다.**

| 만든 것 | 하는 일 |
|---|---|
| 데이터 스토어 **「카카오 토큰 보관소」** | 액세스·리프레시 토큰을 담아 둔다 |
| 시나리오 **「카카오 토큰 갱신 (5시간마다)」** | 만료 전에 새 토큰으로 갈아 끼운다 |
| 시나리오 **「카카오톡 나에게 보내기 — 연결 확인용」** | 준비가 됐는지 한 번에 확인한다 |

구조를 둘로 나눈 이유는 **액세스 토큰이 6시간이면 만료**되기 때문입니다.
알림 시나리오는 보관소에서 꺼내 쓰기만 하고, 갱신은 별도 시나리오가 맡습니다.

남은 것은 **카카오 개발자센터에서 인가를 한 번 받아 리프레시 토큰을 Make 에 넣는 일**입니다.
절차는 **[`카카오톡_준비.md`](./카카오톡_준비.md)** 에 있습니다.

**확인(4단계)까지 끝난 경우에만 카카오톡으로 바꿉니다.** 준비가 안 된 채로 수업에 들어가면
토큰에서 막혀 실습이 통째로 멈춥니다. 지금은 **Gmail 이 정상 경로**이고 카카오톡은 선택지입니다.
