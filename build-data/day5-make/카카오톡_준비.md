# 카카오톡 알림 준비 (2026-09-08)

DAY 5 의 알림을 **카카오톡 「나에게 보내기」** 로 받기 위한 준비 절차입니다.
Make 쪽(보관소·갱신 시나리오·보내기 데모)은 **이미 만들어 두었습니다.**
남은 것은 카카오 개발자센터에서 인가를 한 번 받아 **리프레시 토큰을 Make 에 넣는 일**입니다.

> **토큰과 키를 채팅창이나 문서에 붙여넣지 마세요.** 모두 Make 화면에서 직접 넣습니다.
> 이 문서에도 값은 하나도 적혀 있지 않습니다.

---

## 왜 이런 준비가 필요한가

Make 에는 카카오 커넥터가 없어 **HTTP 모듈로 직접** 부릅니다. 그런데
**카카오 REST API 액세스 토큰은 6시간이면 만료**됩니다. 수업 중에 만료되면 알림이 조용히 멈춥니다.

그래서 구조를 둘로 나눴습니다.

```
[카카오 토큰 보관소]  ← 5시간마다 도는 「카카오 토큰 갱신」 시나리오가 새로 채운다
        ↓ 꺼내 쓰기만
[알림 시나리오]      ← 수업에서 만드는 것
```

리프레시 토큰(2개월)은 **갱신할 때마다 새로 발급되고 옛것은 폐기**되므로,
사람이 손으로 관리하면 반드시 어긋납니다. 보관소가 그 역할을 맡습니다.

---

## 1단계 — 카카오 개발자센터 (브라우저)

<https://developers.kakao.com> → 내 애플리케이션

1. **앱 선택 또는 생성.** 사이트 로그인에 쓰는 앱을 그대로 써도 되고, 새로 만들어도 됩니다.
   - 새로 만드는 편을 권합니다. **로그인용 앱에 손대면 사이트 로그인이 영향을 받을 수 있습니다.**
2. **카카오 로그인 → 활성화 ON**
3. **카카오 로그인 → Redirect URI 등록**: `https://build-data.jobability.co.kr`
   - 학습사이트는 HashRouter 라 `?code=...` 가 주소 앞쪽에 붙습니다. 화면은 평소대로 뜨고,
     **주소창에서 code 값만 복사**하면 됩니다. 별도 페이지를 만들 필요가 없습니다.
4. **카카오 로그인 → 동의항목 → `talk_message`(카카오톡 메시지 전송) 를 「사용」으로**
   - **이것이 핵심입니다.** 이 동의항목이 없으면 뒤 절차가 전부 실패합니다.
   - 「나에게 보내기」는 **비즈니스 앱 전환도, 검수도 필요 없습니다.**
5. 적어 둘 값 두 가지 — **앱 키 → REST API 키**, **보안 → Client Secret**
   - Client Secret 은 **기본이 「사용함」** 입니다. 사용함이면 뒤에서 함께 넣어야 합니다.

## 2단계 — 인가 한 번 받기

**① 브라우저 주소창에 아래를 넣습니다.** `{REST_API_KEY}` 만 본인 값으로 바꿉니다.

```
https://kauth.kakao.com/oauth/authorize?client_id={REST_API_KEY}&redirect_uri=https://build-data.jobability.co.kr&response_type=code&scope=talk_message
```

동의 화면에서 **「카카오톡 메시지 전송」에 동의**하면 학습사이트로 돌아옵니다.
그때 **주소창의 `?code=` 뒤 문자열**을 복사합니다. (이 코드는 몇 분이면 만료됩니다 — 바로 ②로)

**② 터미널에서 토큰을 받습니다.**

```sh
curl -X POST 'https://kauth.kakao.com/oauth/token' \
  -H 'Content-Type: application/x-www-form-urlencoded;charset=utf-8' \
  -d 'grant_type=authorization_code' \
  -d 'client_id={REST_API_KEY}' \
  -d 'client_secret={CLIENT_SECRET}' \
  -d 'redirect_uri=https://build-data.jobability.co.kr' \
  -d 'code={방금 복사한 code}'
```

- Client Secret 을 「사용 안 함」으로 두었다면 `client_secret` 줄을 빼세요.
- 응답에 `access_token`·`refresh_token`·`expires_in`·`refresh_token_expires_in` 이 옵니다.
- **`refresh_token` 이 필요한 값입니다.** `expires_in` 이 6시간(21599초)쯤인 것도 확인해 두세요.

## 3단계 — Make 에 넣기

**① 토큰 보관소** — Make → Data stores → **「카카오 토큰 보관소」** → 레코드 `me` 편집

| 칸 | 넣을 값 |
|---|---|
| `refresh_token` | 2단계에서 받은 **refresh_token** |
| `access_token` | 2단계에서 받은 **access_token** (비워 둬도 갱신 시나리오가 채웁니다) |
| `updated_at` | 오늘 날짜 (안내 문구를 지우고) |

**② 두 시나리오의 HTTP 모듈에 키 넣기**

| 시나리오 | 넣을 곳 |
|---|---|
| **카카오 토큰 갱신 (5시간마다)** | 2번 모듈의 `client_id` = REST API 키 · `client_secret` = Client Secret |
| | Client Secret 을 안 쓰면 그 줄을 **지웁니다** |

「카카오톡 나에게 보내기 — 연결 확인용」에는 넣을 키가 없습니다.
보관소에서 액세스 토큰을 꺼내 쓰기 때문입니다.

## 4단계 — 되는지 확인 (순서대로)

1. **「카카오 토큰 갱신」을 한 번 수동 실행** → 보관소의 `access_token`·`updated_at` 이 바뀌면 성공
2. **「카카오톡 나에게 보내기 — 연결 확인용」을 실행** → 내 카카오톡에 알림이 오면 성공
3. 되면 **「카카오 토큰 갱신」시나리오를 켭니다(ON)** — 5시간마다 알아서 돕니다

**막히면 여기부터 봅니다.**

| 증상 | 원인 |
|---|---|
| 갱신에서 `invalid_client` | REST API 키 또는 Client Secret 이 틀렸다 |
| 갱신에서 `invalid_grant` | 리프레시 토큰이 만료됐거나 이미 회전됐다 → 2단계를 다시 |
| 보내기에서 `insufficient scope` | `talk_message` 동의항목이 꺼져 있거나 동의 없이 인가받았다 |
| 보내기에서 401 | 액세스 토큰이 만료 → 갱신 시나리오를 한 번 돌린다 |

## 5단계 — 수업에서 붙이기 (9/28~30)

준비가 끝나 있으면 알림 시나리오에 붙이는 것은 모듈 두 개입니다.

```
Data store → Get a record (key: me)     ← 토큰 꺼내기
HTTP → Make a request                    ← 나에게 보내기
   POST https://kapi.kakao.com/v2/api/talk/memo/default/send
   Authorization: Bearer {{액세스 토큰}}
   Body: x-www-form-urlencoded, template_object = (아래 JSON)
```

```json
{"object_type":"text","text":"[점검표 불량] {{장비ID}} · {{점검일자}} — 불량 {{불량수}}건\n{{불량항목}}\n점검자: {{점검자}}","link":{"web_url":"https://build-data.jobability.co.kr","mobile_web_url":"https://build-data.jobability.co.kr"},"button_title":"학습사이트 열기"}
```

**`text` 는 최대 200자입니다.** 불량 항목이 많으면 잘리므로 앞부분만 싣고 자세한 것은
시트에서 보게 합니다 — 「알림은 짧게, 기록은 전부」가 원칙입니다.

## 남는 제약 (알고 쓰기)

- **「나에게 보내기」는 강사 본인에게만 갑니다.** 수강생 각자의 카카오톡으로 보내려면
  「친구에게 보내기」가 되어야 하는데 **권한 신청(검수)** 이 필요하고 1회 5명·일/월 쿼터가 있습니다.
- 고객·현장 담당자에게 보내는 실제 운영은 **알림톡**(Make 의 `solapi` 앱) 영역입니다.
  발신프로필 등록·템플릿 사전승인·건당 과금이 붙습니다.
- **리프레시 토큰은 2개월**입니다. 갱신 시나리오를 켜 두면 자동으로 회전하지만,
  **두 달 넘게 꺼 두면 만료**되어 2단계를 다시 밟아야 합니다.

## 이 준비가 안 끝나면

**Gmail 로 진행합니다.** 알리는 자리만 다를 뿐 「모든 건은 기록하고 이상한 건만 알린다」는
설계는 같습니다. 수업 당일에 토큰에서 막히는 것이 가장 나쁜 결과이므로,
**4단계 확인까지 끝난 경우에만 카카오톡으로 바꿉니다.**
